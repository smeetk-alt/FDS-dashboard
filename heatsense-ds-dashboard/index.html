Why arrays here

A fixed-capacity registry (here capped at 50 stations, matching #define MAX 50 in the C source) is the simplest structure: O(1) access by position, O(n) search by station ID, and insert/delete are restricted to the last slot to keep the operation O(1) rather than shifting the whole array.

Why postfix

        
Postfix notation needs no parentheses and no operator-precedence lookup at evaluation time, each token is either pushed (operand) or immediately applied to the top two stack values (operator), which is exactly how a calculator or formula engine evaluates the heat-index expression at runtime.

      

      
C source

      

      
↓ exp3_heatindex_stack.c

    
      

        
Notes

        
Key concepts

        
    
          
  • LIFO: the last element pushed is the first popped.
    • 
          
  • Linked-list stack: push and pop happen at the head, so both are O(1) and the stack never overflows (only memory limits it).
    • 
          
  • Infix to postfix: operands go straight to the output; operators wait on the stack until a lower or equal precedence operator arrives.
    •

  • Forgetting to pop leftover operators at the end of the expression.

Counter method

        
Rather than reserving an empty slot to tell "full" from "empty", this implementation keeps an explicit count. Both front and rear wrap around with (index + 1) % SIZE, so the 5 slots are reused indefinitely instead of a plain array that would run out of room after 5 dispatches.

      

      
C source

      

      
↓ exp4_dispatch_queue.c

    
      

        
Notes

        
Key concepts

        
    
          
  • FIFO: the first item enqueued is the first dequeued.
    • 
          
  • Circular array: after the last slot, rear and front wrap to index 0 via (index + 1) % SIZE, so freed slots are reused.
    • 
          
  • Counter method: a separate count tells full (count == SIZE) from empty (count == 0) without wasting a slot.

BST property

        
Every left subtree holds temperatures strictly less than its parent, every right subtree strictly greater, so an inorder traversal always visits nodes in sorted order without any separate sort step, and search/insert/delete run in O(log n) on a balanced tree.

      

      
C source

      

      
↓ exp5_station_bst.c

    
      

        
Notes

        
Key concepts

        
    
          
  • BST property: left subtree < node < right subtree, for every node.
    • 
          
  • Traversals: inorder gives sorted output; preorder copies a tree; postorder deletes a tree safely.
    • 
          
  • Delete has three cases: leaf (remove), one child (replace with that child), two children (replace with inorder successor, then delete the successor).
    •

Why BFS for advisory spread

        
BFS visits all directly-adjacent regions before moving further out, exactly matching how a heatwave advisory would reasonably propagate ring by ring through neighbouring districts, rather than DFS's deep-first behaviour which would tunnel far from the epicentre before covering its immediate neighbours.

      

      
C source

      

      
↓ exp6_region_network_bfs.c

    
      

        
Notes

        
Key concepts

        
    
          
  • Adjacency matrix: an n x n grid where adj[i][j] = 1 means an edge joins i and j. Undirected graphs give a symmetric matrix.
    • 
          
  • BFS: explores all neighbours of a node before going further, so it finds the fewest-edge path from the start.
    • 
          
  • visited[]: marks a node when it is enqueued, not when it is dequeued, to avoid adding it twice.
    • 
        

        
Complexity

        
RepresentationBFS timeSpace

          
Adjacency matrixO(V^2)O(V^2)

          
Adjacency listO(V + E)O(V + E)

        

        
Common mistakes

        
    
          
  • Marking a node visited only when dequeued, which can enqueue the same node many times.
    • 
          
  • Forgetting to set the matrix symmetrically for an undirected graph.
    • 
          
  • Starting index out of range (the lab uses 0-indexed regions).

Historical daily max-temperatures, sorted with quicksort, then searched with binary search.

Sorted records

      


      

        
        
      

      


      

        
Why sort first

        
Binary search only works on a sorted sequence: each comparison with the middle element halves the remaining search space, giving O(log n) lookups instead of linear search's O(n); the one-time O(n log n) quicksort pays for itself over many repeated searches.

      

      
C source

      

      
↓ exp7_history_sort_search.c

    
      

        
Notes

        
Key concepts

        
    
          
  • Precondition: binary search only works on a sorted array.
    • 
          
  • Quicksort: picks a pivot, partitions smaller and larger values around it, then recurses on each side.
    • 
          
  • Binary search: compares the key with the middle element and discards half the remaining range each step.
    • 
        

        
Complexity

        
AlgorithmBest / averageWorst

          
QuicksortO(n log n)O(n^2) (already sorted input, bad pivot)

          
Binary searchO(log n)O(log n)

        

        
Common mistakes

        
    
          
  • Running binary search on an unsorted array and reporting "not found" incorrectly.
    • 
          
  • Using (low + high) / 2 with very large indices (overflow); low + (high - low) / 2 is safer.
    • 
          
  • Off-by-one errors in low/high updates, which can cause an infinite loop.

Hash table (10 slots)

      


      

        
Collision example

        
Station 6 and station 16 both hash to index 6 (6 % 10 = 6, 16 % 10 = 6). The second insert probes forward to the next empty slot; search and delete follow the exact same probe sequence so they still find it. A deleted slot is marked with a tombstone rather than emptied outright, so later searches don't stop early and miss keys stored past it.

      

      
C source

      

      
↓ exp8_station_hashtable.c

    
      

        
Notes

        
Key concepts

        
    
          
  • Hash function: key % SIZE maps any key to a slot index.
    • 
          
  • Linear probing: on a collision, try the next slot, wrapping around the circular array.
    • 
          
  • Tombstone: a deleted slot is marked, not emptied, so later searches keep probing past it.
    •
